# Task Service

Сервис для управления задачами с HTTP API на Go.

## Требования

- Go `1.23+`
- Docker и Docker Compose

## Быстрый запуск

```bash
cp .env.example .env
docker compose up --build
```

После запуска сервис доступен по адресу `http://localhost:8080`.

Если postgres уже запускался ранее со старой схемой — пересоздай volume:

```bash
docker compose down -v
docker compose up --build
```

## Swagger

```
http://localhost:8080/swagger/
```

## API

Базовый префикс: `/api/v1`

### Задачи

| Метод | Путь | Описание |
|-------|------|----------|
| POST | /tasks | Создать задачу |
| GET | /tasks?limit=20&offset=0 | Список задач |
| GET | /tasks/{id} | Получить задачу |
| PUT | /tasks/{id} | Обновить задачу |
| DELETE | /tasks/{id} | Удалить задачу |

### Расписания

| Метод | Путь | Описание |
|-------|------|----------|
| POST | /schedules | Создать расписание |
| GET | /schedules?limit=20&offset=0 | Список расписаний |
| GET | /schedules/{id} | Получить расписание |
| PUT | /schedules/{id} | Обновить расписание |
| DELETE | /schedules/{id} | Удалить расписание |
| POST | /schedules/{id}/generate | Сгенерировать задачи за период |

### Типы расписаний

| Тип | Обязательные поля | Описание |
|-----|-------------------|----------|
| `daily` | `day_interval`, `start_date` | Каждые N дней начиная с даты |
| `monthly` | `day_of_month` (1–30) | Каждое N-е число месяца |
| `specific_dates` | `dates` | Только указанные даты |
| `even_odd` | `parity` (`even`/`odd`) | Чётные или нечётные дни месяца |

### Примеры запросов

Создать ежедневное расписание:

```bash
curl -X POST http://localhost:8080/api/v1/schedules \
  -H "Content-Type: application/json" \
  -d '{
    "title": "Обзвон пациентов",
    "schedule_type": "daily",
    "day_interval": 1,
    "start_date": "2026-01-01T00:00:00Z"
  }'
```

Сгенерировать задачи за апрель:

```bash
curl -X POST http://localhost:8080/api/v1/schedules/1/generate \
  -H "Content-Type: application/json" \
  -d '{"from": "2026-04-01T00:00:00Z", "to": "2026-04-30T00:00:00Z"}'
```

## Проектные решения

**Расписание как шаблон**

`Schedule` — отдельная сущность, не поле задачи. Это позволяет одному расписанию порождать множество задач, а задачам оставаться независимыми объектами, которые можно выполнять, редактировать и удалять по отдельности.

**Генерация задач по запросу**

Задачи создаются явным вызовом `POST /schedules/{id}/generate` с указанием диапазона дат. Явный вызов проще, тестируемее и даёт пользователю контроль над периодом.

**Идемпотентность генерации**

Повторный вызов `generate` за тот же период не создаёт дублей. Каждый факт генерации фиксируется в таблице `schedule_instances` с уникальным ключом `(schedule_id, scheduled_date)`. Перед созданием задачи проверяется наличие записи через `SELECT EXISTS`.

**Обработка `day_of_month` для коротких месяцев**

Поддерживаются значения от 1 до 31. Если указанное число не существует в конкретном месяце (например, 31 апреля или 29 февраля в невисокосный год) — задача для этого месяца не создаётся, остальные месяцы не затронуты.

**Пагинация в List**

Дефолт — 20 записей, максимум — 100. Если `limit` не передан или передан некорректный — используется дефолт. Это защищает от случайных запросов без параметров на больших объёмах данных.

**Название задачи при генерации**

Сгенерированная задача получает название вида `"Обзвон пациентов (2026-04-07)"` — к заголовку расписания добавляется дата. Это позволяет различать задачи одного расписания в общем списке.
